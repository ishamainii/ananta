Forward-modeling IllustrisTNG galaxies into mock MaNGA observations

Simulations and surveys speak different languages. IllustrisTNG gives you particles: stellar positions, ages, metallicities. MaNGA gives you spectra on a hexagonal bundle of fibers. To compare them fairly, I convert simulated galaxies into synthetic integral-field data cubes that look like MaNGA observations, then analyze them with GIST, the same pipeline used on real data. The science goal is to test how viewing angle affects the MBH–σ* relation in AGN-hosting galaxies.

The pipeline

Phase one was a controlled parameter study. I held the fiber bundle fixed (fib_n = 7) and varied the field of view and the galaxy's physical scale (re_kpc), comparing edge-on and face-on views, to see what each choice changes in what GIST can recover.

Why it couldn't scale

13.1 minmain spectral step, on 6 CPUs
6.3 / 10 GBmemory used, against the cap
381parallel tasks, each loading its own copy of the particle data
2 + 6runs for a 2×4 sweep, instead of 8 full runs

I timed each stage. The spectral step dominated, and because every one of its 381 parallel tasks loaded its own copy of the particle data, adding cores would have run out of memory before it ran faster. Reading the code turned up two more things:

  • re_kpc only affects the final regrid. So a 2×4 parameter sweep needs 2 full runs plus 6 short regrids, not 8 full runs. That's 75% fewer full runs.
  • Cached intermediate files didn't record their settings. A stale file could be silently reused for the wrong configuration.

An LLM assistant that reads the real outputs

To stop wasting runs, I wrote a small tool-using LLM assistant in Python. It has five tools that read our actual output files: it lists available results, summarizes timing logs, plans parameter sweeps using the reuse rule above, and checks data cubes for the zero, negative or NaN noise values that make GIST fail partway through a run. It's connected to our live outputs, so a bad cube gets flagged in seconds instead of after a failed run.

What's next

  • Share particle data across workers to lift the memory ceiling, then measure speedup at 6, 12 and 24 workers.
  • A LangChain-based version of the assistant (in progress).
  • Scale from one galaxy to a sample of subhalos spread in stellar mass.
